# HyperMM — веб-инструмент: с чего начать

Документ для отдельного чата, посвящённого разработке сайта. Содержит всё, что
нужно, чтобы приступить, не читая исследовательскую часть целиком.

## Что это за проект

ВКР по маркет-мейкингу. Работа измеряет, насколько выводы бэктеста маркет-мейкинга
определяются не стратегией, а произвольным допущением о том, исполнилась бы
пассивная заявка, — так называемой fill-моделью. Данные: открытый L4-датасет
Hyperliquid *An Open Book* (Zenodo 18184441), три потока — жизненный цикл заявок,
изменения стакана, сделки.

Подробности исследования — в документе проекта «HyperMM — журнал работы»
(он же лежит в репозитории как `docs/JOURNAL.md`). Читать целиком для работы над
сайтом не обязательно; нужен раздел «Карта проекта» в его начале.

## Где код

Репозиторий на машине автора: `~/Desktop/hyperMM`. Чтобы чат его увидел, нужно
подключить эту папку кнопкой «Add folder» в приложении Claude.

Относящееся к сайту:

```
web/index.html          разметка
web/style.css           оформление, светлая и тёмная темы
web/app.js              загрузка данных и отрисовка на canvas
web/README.md           как запустить
hypermm/replay_ui/export.py   сборка data.json из конвейера
docs/UI_ROADMAP.md      план развития, шесть уровней
```

Всё остальное в `hypermm/` — исследовательский конвейер; сайт обращается к нему
только через `export.py`.

## Запуск

```bash
cd ~/Desktop/hyperMM
source .venv/bin/activate
python -m hypermm.replay_ui.export     # соберёт web/data.json, около 45 с
python -m http.server -d web 8000      # http://localhost:8000
```

Для пересборки данных нужны сырые файлы в `data/raw/`; они в git не хранятся.
Если их нет, `data.json` можно взять готовым — страница без конвейера работает.

## Формат data.json

Страница получает один файл. Цены и объёмы — целые в единицах `1/meta.scale`
(scale = 10⁸); делить на `scale` при отображении. Время — секунды от начала часа.

```
meta     coin, date, hour, scale
stats    changes, orders, fillRate, medianSpread,
         secondsToFill, secondsToCancel, medianAhead
series   second[720], mid[720], spread[720]      — mid и spread могут быть null
frames   [{bids: [[цена, объём], …≤12], asks: […]}] × 720
queue    [{bucket, orders, ahead, fillRate}] × 10
outcomes [{outcome, orders}] × 3   — filled / cancelled / resting
```

`frames[i]` соответствует `series.second[i]`: один и тот же момент времени.
Уровни в `bids` идут от лучшей цены вниз, в `asks` — от лучшей вверх.

Размер файла — около 0.48 МБ на час.

## Принципы, которых стоит держаться

**Без сборки.** Ванильные HTML, CSS, JS. Никакого `npm`, никаких зависимостей,
никакого шага сборки. Инструмент должен открываться и работать через годы.

**Данные отдельно от страницы.** Python готовит `data.json`, страница только
рисует. Всё тяжёлое считается заранее: час — это миллионы событий, в браузер
уходит полмегабайта.

**Цвет.** Покупка зелёным `#1e8f4e`, продажа красным `#d6432e` (в тёмной теме
`#34c76f` и `#ef5b42`) — привычная для торговых интерфейсов пара. Изначально была
выбрана сине-оранжевая палитра, прошедшая проверку на различимость при дальтонизме
(красно-зелёная её не проходит); 26 августа 2026 автор сознательно сменил её на
красно-зелёную, см. `docs/JOURNAL.md`. Сторона дополнительно подписана словом, а не
передаётся только цветом. Все цвета — через переменные CSS в начале `style.css`,
обе темы объявлены явно.

**Ограничения на экране.** Отсутствие рыночного отклика, разогрев книги в начале
часа, унаследованные отметки времени — то, что инструмент скрывает, вводит в
заблуждение сильнее текста.

**Страницу надо смотреть, а не только писать.** Три дефекта вёрстки первой версии
были невидимы в коде и обнаружились только на снимке экрана.

## Что дальше по плану

Полностью — в `docs/UI_ROADMAP.md`. Кратко, по возрастанию ценности:

1. **Жизнь одной заявки** — история конкретной заявки на трёх полосах общей оси:
   цена, тающий объём впереди, события соседей по уровню.
2. **Четыре fill-модели рядом** — главная функция: когда сочла бы заявку
   исполненной каждая модель против того, когда она исполнилась на самом деле.
3. **Поставить свою заявку** — выбрать момент, цену, размер, увидеть очередь и
   ответы моделей.
4. **Стратегия за час** — один квотер под четырьмя допущениями даёт четыре разных
   ответа.
5. **Токсичность и блочная семантика** — markout, поток отклонённых заявок,
   покадровый реплей блока.
6. **Открытый инструмент** — свои данные, своя fill-модель, общая шкала сравнения.

Уровень 1 упирается в траекторию объёма впереди во времени: сейчас известна
только позиция в очереди в момент постановки. Эта величина считается в
исследовательской части и появится там.

## Чего в коде пока нет

- траектории объёма впереди (только значение при постановке);
- самих fill-моделей — они следующий этап исследования;
- признаков на момент постановки: спред, дисбаланс, глубина, волатильность;
- отклонённых post-only заявок: требуют отдельного файла датасета.
